## 固定契约
- agent 表示 AI 执行队列/执行中；needs-human 优先暂停所有自动执行与合并；merge-approved 表示当前交付的批准。
- 新交付由宿主持久化接管，再移除 agent。移除中/失败时 handing_off，不允许合并；后台重试可恢复。接管记录包含原授权 cycle 和 agent 摘除事件，新授权使旧交付失效。
- 无 agent 的有效交付由独立 GitHub 宿主检查器读取私有收据持续检查；不走 AI runner，无 AI 次数/会话/并发消耗，重启可恢复。真实 AI 仍运行时不合并。
- 再加 agent 是重新执行请求；旧交付退出合并，旧批准撤销，新交付须重新批准。暂停恢复也按 agent 领取核对现有 PR。
- 看板继续优化：可靠发布 PR 意见、撤销批准、再加 agent；暂停保持暂停，运行中不重贴。普通评论不触发调度。marker 仅用于幂等，不作为 AI 调度信号。
- 宿主把可修复 CI/冲突退回执行：先保存 superseded，再撤批准、加 agent；保留累计修复预算，超限暂停。网络未知重试，不假定成功。
- 意见阅读/回应/验证/复用 PR 由 WORKFLOW 定义，不再由 Runner 注入业务提示词。保留人工控制评论权限保护。
- API 输出明确 stage/reason/pr/sha/observed_at；看板只映射，不靠 merge_poll 推断。真实运行优先于排队；暂停期间仍有真实运行显示正在停止。陈旧数据显示同步异常。
- PR open 不等于交付；已关闭未合并、已合并收尾、已完成区分。GitHub 是完成事实来源。最终 merge 重查关闭/暂停/新授权。已提交 merge 无法保证撤回，必须确认结果。
- 每次新交付撤销旧标签批准，标签批准须晚于交付事件下界，避免同秒时间精度误判；Review 对应交付后的 SHA。看板批准携带交付 UUID 和 SHA，由有凭据保护的宿主接口在收据锁内核对后写入。无有效交付不提供批准按钮。
- 收据损坏/仓库不符/未知授权 fail closed；旧已发布未暂停记录验证授权后迁移接管；blocked 保持暂停。不用真实 GitHub 数据做写入测试。
- GitHub DELETE 标签无条件更新：接管摘除后发现最新 grant 变化时，先持久化 requeue_pending 再恢复 agent，保全用户重新执行意图；若 needs-human 存在则保持暂停不恢复。无法核实时保持错误/待恢复，不合并。覆盖读取后插入新grant再DELETE的竞争测试。
- 摘除 agent 前持久保存 delete_grant 意图；旧收据无 agent 且没有该意图时保持暂停，不把人工摘标签误认为完成接管。已合并且 Issue 已关闭、标签已清理的任务，重启只确认本地收据，不重复远端写入。

## 验收
AC01 加 agent→真实运行→持久化交付→移除 agent；接管失败不合并，重试幂等。
AC02 无 agent 轮询门禁，重启恢复，不进入 running/占槽/创建会话。
AC03 再加 agent 返工或恢复使旧交付失效，WORKFLOW 处理所有审核意见；普通评论不唤醒。
AC04 暂停优先；返工/批准/暂停竞争最终重读；新交付不沿用旧批准。
AC05 修复排队、预算有限、网络错误重试；关闭/合并确认正确。
AC06 API/看板展示明确阶段和原因；请求失败/部分成功/不确定不伪成功。
AC07 Python/HTTP/JS/隔离浏览器验收、空闲加载、两服务就绪，GH155保持暂停，无真实AI或合并测试。
